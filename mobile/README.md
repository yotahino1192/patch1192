# Patch iOS — Phase 1

The iOS target bundles the existing React application with Capacitor. Next.js still serves the web app and all APIs. No authentication, ownership migration, notifications, or widgets are included. This is a development shell, not an App Store-ready release.

## Requirements

- Node 22 (`.nvmrc`), `npm ci`
- Xcode 26 or later, an installed iOS Simulator runtime
- Internet access for the first Swift Package Manager resolution
- Minimum supported iOS: 16.4 (matches the existing Tailwind 4/Safari baseline)

## Run locally

Terminal 1, repository root:

```sh
npm run dev
```

This uses the existing server environment and database. For disposable testing, set a separate `TURSO_DATABASE_URL=file:/tmp/patch-ios-dev.db` and empty `TURSO_AUTH_TOKEN` / `OPENAI_API_KEY` when starting the backend. Do not reset the existing database to test onboarding.

Terminal 2:

```sh
npm run ios:sync:local
npm run ios:open
```

In Xcode:

1. Open `ios/App/App.xcodeproj` (SPM; no CocoaPods workspace is required).
2. Allow package resolution to finish.
3. Select the **App** scheme and an iPhone Simulator destination, e.g. iPhone 17 Pro.
4. Use **Product → Run** (Command-R). Simulator builds do not require a paid developer membership or a signing Team.
5. Keep the backend running. After React/CSS/config changes, run `npm run ios:sync:local` again, then Run in Xcode. There is no remote website/live-reload URL in the native configuration.

Alternatively, `npm run ios:run` builds/syncs the local bundle and invokes Capacitor's device chooser/run command.

`npm run mobile:dev` serves the shared frontend at `http://127.0.0.1:5173`; `/api` is proxied to the configured backend. This browser preview is useful for UI iteration but does not exercise native HTTP or WKWebView.

## Backend environments

- Local build: `npm run mobile:build:local`; default `http://localhost:3001`.
- Override with `PATCH_API_URL`, or `mobile/.env.development.local`.
- Production build: set `PATCH_API_URL=https://your-real-backend.example.com` in the shell or `mobile/.env.production.local`, then `npm run ios:sync`.
- `npm run mobile:build` builds the production bundle without syncing Xcode.
- The URL must be an origin, without `/api`, a query, credentials, or fragment. Production requires HTTPS and fails if the URL is absent. There is deliberately no guessed Vercel URL.
- The URL is public and embedded at build time. Never place server/API keys in mobile environment files. The root server `.env` is not exposed to the mobile bundle.
- Simulator `localhost` reaches the Mac. A physical device needs a reachable backend, preferably HTTPS. If using LAN development, local-network permissions/firewall behavior require device testing.

Release/Archive builds validate `patch-build.json` and reject missing assets, development bundles, or non-HTTPS origins. `NSAllowsLocalNetworking` allows local development; arbitrary insecure network loads are not enabled. A production-configured shell is still not safe for public use until authentication and user separation are implemented.

## Architecture and assets

- `main.tsx` imports `app/page.tsx` directly, including its existing LanguageProvider, components and learning logic.
- `lib/api-client.ts` defaults to unchanged same-origin `fetch` on the web.
- Native startup configures JSON requests through `CapacitorHttp`. This avoids changing backend CORS or globally patching asset/PDF fetches. HTTP errors, including 409, are preserved for existing retry logic. This transport currently supports JSON APIs, not uploads/streaming/abort signals.
- Browser development uses Vite's proxy; the Next.js app does not depend on Vite or Capacitor initialization.
- `public/`, generated PDF worker/cmaps, CSS, and Fontsource fonts are bundled. The application UI needs no Google Fonts request at runtime. The existing Next.js font workflow remains unchanged.
- localStorage retains `loop-workspace-v1` in the app's WKWebView. It is separate from Safari/Chrome storage. Keep the Capacitor origin stable; uninstalling or clearing app data loses local drafts.
- `ios/App/CapApp-SPM/Package.swift` is generated by `cap sync`; `Package.resolved` pins the native dependency. Commit the native project, not copied `App/public`, DerivedData or generated Capacitor config.

## Manual smoke checklist

- Fresh temporary DB: onboarding → choose a preset → three cards → completion → home.
- Existing data: sets → open set → learn/review → correct/incorrect → return/resume.
- Start a draft/session, force-quit, relaunch and confirm restoration.
- Disable networking during an answer and retry; confirm a single history entry.
- Scroll long screens, use Japanese keyboard, rotate, check safe areas and dialogs.
- Import text/PDF/Office files using iOS Files; check larger files and worker loading.
- Verify images/fonts offline while treating backend-dependent operations as online-only.

## Distribution work intentionally pending

`com.patch.learning` is a provisional development Bundle ID. Before signing/distribution, configure your registered identifier in both Capacitor and Xcode, Team, final app icon/launch branding, privacy declarations and App Store metadata. The generated Capacitor app icon is a placeholder. No authentication, APNs, WidgetKit, App Groups or Associated Domains capabilities are enabled.

The backend still identifies everyone as `loop-owner`. Do not ship this shell publicly or embed a hosting-protection bypass secret. A Vercel deployment protected by an interactive login may reject native API calls; configure a suitable private test environment instead of assuming it will work.
