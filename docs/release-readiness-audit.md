The app manifest currently covers required-reason API access, **not a completed collection disclosure**. It has no `NSPrivacyCollectedDataTypes` key; this does not mean “Data Not Collected.” App Store privacy answers must cover email, account identifiers, user-provided learning/chat content, learning interactions, and relevant provider diagnostics/usage records. Final purpose/linkage/retention and any manifest collection entries require provider settings/legal review. Do not copy generic categories or promise no collection. No advertising/tracking SDK or ATT flow was found in current code. No new privacy capabilities were enabled.

Before upload, inspect **device** archive recursively, compare manifest list with linked frameworks/resources, generate Xcode privacy report, inspect entitlements for App/Widget, and run Apple's Validate/upload processing. A simulator manifest inspection is not proof of store acceptance. See [Apple required-reason API documentation](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api).

## Legal/public consistency and values Yota must supply

`lib/public-pages/config.ts` has these 19 null fields: operatorName, contactEmail, legalAddress, serviceCountries, processingRegions, effectiveDate, retentionPolicy, backupRetention, deletionTiming, rightsProcedure, supportResponse, eligibility, contentRights, commercialTerms, liability, governingLaw, disputeResolution, serviceChanges, revisionNotice.

Supply actual operator name/address and working support email; release countries/ages and effective date; each processor's actual regions/transfers; retention by data class (including consent, AI retry results/usage, deletion tombstones and backups); deletion time target and backup deletion/restore procedure; rights request/support response process; content licensing, price/payment/cancellation/refund terms or explicit free-service terms; liability/law/jurisdiction and change/end-of-service notices. Also supply the final HTTPS public host for `/privacy`, `/terms`, `/support`. Do not publish made-up values or merely switch the draft flag; content contains “準備版/未確定” prose too.

Cross-check against code:

- Public account deletion describes reauthentication, immediate access stop, asynchronous deletion, retries, minimal retained records and limits of offline/backup deletion. This matches `db/account-deletion.ts` and `lib/deletion-worker.ts` **as designed**. Production completion is not established until the scheduler and R03 rehearsal exist. Claims of zero retained data or instant provider erasure would be false.
- Public AI disclosure matches input/extracted text, card/source/chat context/settings, OpenAI recipient, consent/withdrawal and post-response fences. Gateway consent checks exist; `lib/ai/execution.ts` sets `store:false`. This is not a promise about all provider retention. ai-learning-1/privacy-draft-1 must be reviewed when publishing wording; changes of scope require deliberate version/re-consent handling.
- No backend region, final public URL, legal identity or external service settings were inferred from old documents. Public Vercel/Turso hosting descriptions reflect repository architecture, not verified deployments.

Apple's current [review guidelines](https://developer.apple.com/app-store/review/guidelines/) require usable reviewer access and disclosure/permission for third-party AI. Email-only authentication does not by itself establish a requirement to add a social-login capability; reconsider section 4.8 if adding providers. These are release planning conclusions, not legal approval.
